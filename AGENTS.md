# AGENTS.md

A [tree-sitter](https://tree-sitter.github.io/tree-sitter/) grammar for the Motoko programming language.

## Source of truth

`grammar.js` is the only file you edit to change the grammar. Everything under `src/`
(`parser.c`, `grammar.json`, `node-types.json`, `src/tree_sitter/`) is generated by
`tree-sitter generate` and must never be hand-edited. `parser.c` also embeds the
version from `tree-sitter.json`, so a release bump (`tree-sitter version X.Y.Z`,
which also misses the two root fields of `package-lock.json`) must be followed by
`tree-sitter generate`.

The language bindings and their build files are also generated and must not be
hand-edited. Per `.gitattributes` these include: `bindings/**`, `binding.gyp`,
`CMakeLists.txt`, `Makefile`, `Cargo.toml`, `package.json`, `package-lock.json`,
`setup.py`, `pyproject.toml`, `Package.swift`, and `go.mod`. They are regenerated
with `tree-sitter init --update`.

## Build, test, format

Requires Node 22, a C toolchain, and Rust (for the `dev/` corpus generator). The
[`just`](https://github.com/casey/just) command runner drives the test workflow.

- Install deps: `npm ci --omit peer --omit optional`
- Run tests: `just test` (runs `tree-sitter generate` then `tree-sitter test`)
- Regenerate the test corpus, then test: `just test-generate`
- Accept/update expected parse trees: `just accept`
- Parse the production packages listed in `test/packages.json` at their default
  branch head: `just packages` (clones under `target/packages/`; add a package
  by adding a manifest entry with `repository` and an optional `path`)
- Playground (build wasm + serve): `just play`
- Node binding tests only: `npm test`

Indentation is enforced by `.editorconfig` (2 spaces for JS/JSON/TOML/YAML/SCM,
4 spaces for C/Rust/Python/Swift, tabs for Go and `Makefile`). Line endings are LF
(`.gitattributes`).

## CI (`.github/workflows/ci.yml`)

Three jobs run on push to `main` and on every pull request:

- **bindings-in-sync**: runs `tree-sitter init --update` and fails if `git diff`
  shows any change. If you touch grammar metadata (e.g. `tree-sitter.json`),
  regenerate bindings and commit the result, or this job fails.
- **test**: checks out sibling repos `motoko` and `motoko-core` next to this one,
  then runs `just test-generate` and `just test`, and fails if the regenerated
  `src/` differs from the committed one. The corpus generator in `dev/` expects
  `../motoko` and `../motoko-core` to exist as siblings.
- **packages**: runs `just packages`, which shallow-clones every entry of
  `test/packages.json` at its default branch head and parses all `.mo` files;
  any `ERROR`/`MISSING` node fails the job. Only public repositories can be
  listed, since the job runs with the default `GITHUB_TOKEN`.

## Layout of non-obvious directories

- `dev/` — a Rust program (`cargo run`) that copies `.mo` files from the sibling
  `motoko` and `motoko-core` repos into `test/corpus/generated/` to build test cases.
- `test/corpus/` — tree-sitter test cases. `test/corpus/generated/` is produced by
  `dev/` and is git-ignored; do not commit or hand-edit it.
- `bindings/` — generated per-language bindings (c, go, node, python, rust, swift).
